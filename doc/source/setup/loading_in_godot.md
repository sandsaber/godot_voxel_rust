# Loading the extension in Godot

Godot discovers GDExtensions through `.gdextension` files. Copy the template
from the repository into your project and point it at the library you built.

## 1. Create the `.gdextension` file

```sh
cp rust/voxel-gdext/voxel_gdext.gdextension.in \
   your_project/addons/voxel/voxel_gdext.gdextension
```

Edit the `[libraries]` section so each platform key points at the artifact you
built (paths are relative to the `.gdextension` file):

```ini
[configuration]
entry_symbol = "gdext_rust_init"
compatibility_minimum = 4.7
reloadable = true

[libraries]
linux.x86_64   = "res://addons/voxel/libvoxel_gdext.so"
windows.x86_64 = "res://addons/voxel/voxel_gdext.dll"
macos          = "res://addons/voxel/libvoxel_gdext.dylib"
android.arm64  = "res://addons/voxel/libvoxel_gdext.android.arm64.so"
```

Keep only the keys for platforms you ship. During development you can point a
key straight at `rust/target/...` instead of copying the binary.

!!! warning
    `entry_symbol` must remain `gdext_rust_init` — it is generated by the
    gdext macro and is the library's entry point.

## 2. Open the project

The editor scans for `.gdextension` files at startup and loads the library.
Look for this in the **Output** panel:

```
Initialize godot-rust (API v4.7.stable.official, ...)
voxel-gdext: Scene stage initialized (voxel-core v0.1.0)
```

All classes are now available in GDScript and the inspector under their
**canonical upstream names**: `VoxelTerrain`, `VoxelBuffer`,
`VoxelMesherBlocky`, `VoxelGeneratorWaves`, … Three classes carry a `ZN_`
prefix to avoid clashing with Godot builtins: `ZN_FastNoiseLite`,
`ZN_SpotNoise`, `ZN_Curve`.

## 3. Quick sanity check

```gdscript
extends Node3D

func _ready():
    var terrain := VoxelTerrain.new()
    terrain.set_generator(VoxelGeneratorWaves.new())
    add_child(terrain)

    var viewer := VoxelViewer.new()
    terrain.add_child(viewer)  # viewers must be children of the terrain
```

Run the scene: terrain pages in around the viewer within a second or two.
See [Terrain quickstart](../terrain_setup.md) for the full walkthrough.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| `Could not load GDExtension library` | Wrong `res://` path in `[libraries]`; the file must exist. |
| Classes missing in editor | `entry_symbol` typo, or the library failed to load — check the log above the class errors. |
| Works on Linux, not Windows/macOS | Architecture/profile mismatch — rebuild for that platform with `--release`. |
